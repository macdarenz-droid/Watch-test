5. IMPORTANT: INSTALLING OVER YOUR OLD APP
------------------------------------------
A debug APK is signed with GitHub/Gradle's debug key.
If the app already installed on your phone was signed with your OLD permanent release key, Android will NOT allow this debug APK to update it in place because the signatures differ.

If you still have the old release keystore/signing secrets, configure the signed release workflow instead (Step 6) so the new APK can retain the same signing identity.

If the old signing key is permanently lost, export a Full Backup from the currently installed M•ARC app BEFORE uninstalling it. Then uninstall the old app, install the new debug/new-key APK, and restore your backup. Uninstalling normally removes the old app's private local data.

6. OPTIONAL: RESTORE PERMANENT SIGNING
--------------------------------------
For a signed release that can update a previous release, the SAME old keystore/key must be used.

GitHub > Repository Settings > Secrets and variables > Actions > New repository secret

Create these exact secret names:
MARC_ANDROID_KEYSTORE_B64
MARC_ANDROID_KEYSTORE_PASSWORD
MARC_ANDROID_KEY_ALIAS
MARC_ANDROID_KEY_PASSWORD

MARC_ANDROID_KEYSTORE_B64 must contain the base64 text of the original .jks/.keystore file.

Then open:
Actions > Build Signed M-ARC Release APK > Run workflow

The version fields may be left blank; the workflow generates safe V36.7 run values automatically.
