PHASE 7 — V36.7 CURRENT
------------------------------
Package:
MARC_V36_7_PHASE7_HAPTIC_REMINDER_HEALTH_APK_READY_SOURCE.zip

This is the CURRENT BASE.

User report that triggered Phase 7:
- Haptic feedback did not work on previous versions.
- Training reminders worked but sometimes appeared to toggle themselves OFF.

HAPTIC ROOT CAUSE:
The JavaScript supported Capacitor Haptics, but the APK workflow did NOT install @capacitor/haptics.
Therefore the Settings Haptic toggle could be ON while no native Haptics plugin existed in the APK.

V36.7 haptic fixes:
- APK workflow explicitly installs @capacitor/haptics.
- Build verifies Haptics appears in capacitor.plugins.json.
- Build should fail rather than ship an APK missing Haptics.
- Added Settings “Test haptic” / haptic health behavior so the installed build can report whether it has:
  native Android haptics,
  web vibration fallback,
  or no available feedback API.

TRAINING REMINDER ROOT CAUSES:
1. Reminder resync treated anything other than Android permission “granted” as a reason to write trainingEnabled=false.
   A transient prompt/unknown/plugin timing state could therefore visually switch the user’s preference OFF.
2. Tapping the reminder toggle previously changed UI state but preference was not necessarily persisted until “Save reminder”.
   Closing the sheet before Save could make it appear OFF again.

V36.7 reminder fixes:
- User ON/OFF preference persists immediately when the toggle is tapped.
- Permission/scheduling health no longer rewrites the user preference to OFF.
- User preference and Android scheduling health are separate concepts.
- After scheduling, M•ARC checks Android’s pending notification queue.
- On app resume/pageshow, M•ARC checks the pending queue again.
- If Android silently dropped scheduled training reminders, M•ARC repairs/reschedules them while keeping the user preference ON.
- Custom split rename/delete reminder resync from Phase 3 remains preserved.

REST-COMPLETE NOTIFICATIONS:
These were reviewed separately.
Existing path was already stronger and was preserved:
- allowWhileIdle:true
- exact/precise scheduling when available
- pending notification verification
- 5-second test path

Do not replace this stronger rest-notification path with the softer training-reminder path.
