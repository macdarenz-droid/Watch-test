Gym Finder Architecture

How to add the Gym Finder without breaking the app, a branch or a rule. It's built in small stages that each merge on their own, with the cheapest one first. Every stage after the first only starts if the one before it proves worth it. A red-team agent attacked an earlier draft; its findings are folded in.

01

Ground rules

Data stays on the phoneSearch, sorting and distance run on the device. No location, query or gym choice is sent anywhere in the core stages.
No server changesNo stage touches escobar-worker/**. No API keys, no paid provider, no new deploys.
Own folderNew code lives in src/slices/gymfinder/** and tools/gymfinder/**. Shared files change only at the named lines below.
Hidden until doneA build-time switch hides every entry point, including the in-app search entry and the coach's navigation, until linking passes review.
List before mapA full list works on every phone and offline. The map is an optional layer and never the only way to choose a gym.
Usual gatesEvery stage goes builder → reviewer → CI, with new tests that fail before and pass after, and add-only gate blocks in all 5 themes.
02

Stages

Card names are GYM-0 to GYM-6, so they don't clash with the proposal's test rows GF-01 to GF-14. Green is the core path; amber is optional and needs your yes. The blue step is a go/no-go check.

GYM-0

Find in Maps

core

A "Find a gym" button in the gym picker and in Settings › Gyms opens the phone's maps app already searching for gyms (geo:0,0?q=gym). The maps app handles location with its own permission. Linking stays the normal "Add a gym" step.

GYM-1

Coverage test

go / no-go

Research only, no code. Compare open gym data (Overture, then OpenStreetMap) against a hand-checked gym list in Makati, BGC, Cebu City, Sydney CBD and Parramatta. Measure missing gyms, closed gyms and duplicates, how often IDs change between monthly releases, and file size. Go only if it clearly beats GYM-0 on what a lifter asks: near me, open now, day pass, kg or lb.

Effort 1 dayOutput a report and a go/no-go for GYM-2
GYM-2

Gym catalogue

core if GYM-1 says go

A monthly script builds one compressed gym file per country from one open source, so licences never mix. It drops every phone, website and social field, and scans names and addresses for hidden contacts. Before publishing it checks a minimum count, a maximum change from last month and the schema, and waits for a manual approval. The file ships inside the app (www/) at a versioned path, so there's no hosting, no bill and nothing to go offline.

Files tools/gymfinder/**, a new workflow (supervisor)Needs DuckDB in CI (dependency OK)Effort 1–2 days
GYM-3

Finder list

core

A new hidden panel with a lazy-loaded chunk. It has list and search, with an area-name helper so "BGC", "Ortigas" or "CBD" match, and gym cards that state unknowns plainly. Each card has an "Open in Maps" handoff (geo:0,0?q=lat,lon(Name)) and no phone, website or source. Older search results can never replace a newer search.

Files src/slices/gymfinder/**, router.ts, App.tsx (supervisor)Effort 2 daysGate block GYM-3 in 5 themes, 320–390 px
GYM-4

Link and train

core

"Use as my gym" links a found gym to an existing training gym, or makes a new one within the 8-gym limit. It asks kg or lb, and does not switch your active gym as a side effect. "Train here" uses the existing setup. During a live workout it shows the workout instead of doing nothing. Fixes the gym-guess bug, where Train overrides a gym you just picked. Turns the switch on.

Files models.ts, escobarState.ts, units.ts, Train.tsx (named lines), palace registryNeeds your yes on one saved fieldEffort 2 days
GYM-5

Map view

optional

A themed map layer built with MapLibre, loaded only when opened. Map colours come from the 5 existing themes, with no new theme fields. Credit is plain text, not a link. It falls back to the list during a live workout, without WebGL, or on phones with 2 GB of memory or less. It recovers if the graphics context is lost. Zoom buttons are 44 px.

Needs your yes: map host and new librariesEffort 3–4 daysCheck device: a 2 GB Android 8 phone
GYM-6

Near me

optional

Sorts the list by distance using approximate location only. It asks natively for coarse location, with a short notice first on every Android version. It never centres a map on you, so no area request reveals where you are. Needs privacy policy and Play Data safety updates, published by you.

Files patch_manifest.py (supervisor), privacy docsNeeds your yes: new use of locationEffort 1–2 days + your policy steps
later

Prices

optional

Prices you curate for the top chains in the launch cities: plan, amount, period, conditions and a "checked" date. They hide themselves before they go stale, with a reminder to you first. Gym-submitted prices come only after a verified claim, and that needs your yes on new stored data.

Not built

  • Google Places: its terms forbid showing it on a non-Google map, and it costs about $1,060 a month at 10,000 users.
  • Reading Facebook or Instagram for prices: Meta's terms forbid it. Website scraping, poster OCR and a review queue: too much ongoing cost and risk.
  • Background location and arrival geofences: high Play-rejection risk, weak evidence. Use reminders at your planned workout time instead.
  • Any prototype code: it was written for ChatGPT's widget system and builds HTML from strings.

06

Bug guards

  • Switch off = invisible: a gate probe proves a switch-off build has no entry button, no search entry and no coach route to the panel.
  • Failing tests first: the gym-guess override, linking at the 8-gym limit, "Train here" during a live workout, a vanished link, backup round trip, reset wiping links, and stale search results losing to newer ones. Each fails on main and passes after.
  • Nothing heavy at start-up: a gate check that no map code lands in the main chunk, plus a size budget for the finder chunks. Start-up timing budgets stay as they are.
  • Crash safety: list-only during a live workout and on weak phones; graphics context loss handled; a device check on a 2 GB phone before the map is enabled.
  • Rule guards: no <a> renders inside the finder; no contact strings in the catalogue; the gym's place link never reaches the coach brief.
  • Gate fit: 44 px touch targets, contrast checks, no sideways scroll at 320 px, all 5 themes. The network is stubbed with a fixture catalogue and a small tile file.
  • Bad data can't ship: count, change and schema checks plus a manual approval before any new catalogue goes into the app. The app keeps the last good file.
