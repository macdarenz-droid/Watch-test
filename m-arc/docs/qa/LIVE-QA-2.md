- **User impact:** 'Reset app data' on the error screen does not clear the broken workout data. The same error comes back, but photos and coach chats are deleted.
- **Evidence:** src/app/ErrorBoundary.tsx:22-25 clears localStorage and then calls location.reload(). - **Skeptic:** Confirmed by a run at head. Tapping reset calls resetAppData() and then location.reload() (src/app/ErrorBoundary.tsx:22-25). Vitest: initStore with a saved state, then resetAppData(storage) and flushSave(). Afterwards marc.state.v1 held the old state and marc.escobar.v1 was gone. When anything had changed in memory since the last save, marc.state.v1.backup and backupDay were also written with the old state (store.ts:312-315). So the crashing workout data comes back while chats and photos are deleted. The existing test (tests/error-boundary.test.ts) only checks that clear() is called. The original finding was rated low. I rate this medium because the only way out inside the app does nothing and still deletes other data.
